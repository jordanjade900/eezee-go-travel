## Domain configuration and launch

The default production origin is the client’s current public site, `https://eezeegotravelja.com/`. This local preview is not published and cannot be indexed remotely. If the replacement launches elsewhere, regenerate before deployment:

```powershell
$env:PUBLIC_SITE_URL = 'https://the-confirmed-launch-domain.example/'
npm run build
```

The build runs `tools/seo.mjs` before copying runtime files, updating canonicals, structured-data IDs, sharing URLs, sitemap and robots references together. To update source metadata alone, use `npm run seo:generate`. Never use loopback URLs as production canonicals. If page copy or FAQ answers change, regenerate metadata before publishing.

After public launch, verify the final domain in Search Console, submit the sitemap, validate the live structured data, check CDN crawler access, and configure redirects from replaced old-site URLs. None of those external account or deployment steps have been performed here.

## Meaning of AIO optimization

This implementation supports retrieval through readable, factual HTML, accessible navigation, consistent business identity and structured data matching the page. Google states that normal SEO foundations apply to AI Overviews and AI Mode; no special AI schema or AI text file is required. Inclusion and indexing are not guaranteed. [Google Search Central: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

Schema types follow [Schema.org TravelAgency](https://schema.org/TravelAgency). Local JSON syntax, unique metadata, crawler endpoints, visible FAQ correspondence and sitemap URL counts are checked by `tools/check-polish.mjs`. This is local verification, not a claim of Google rich-result eligibility or guaranteed rankings.
